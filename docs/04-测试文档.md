# 04 · 测试文档

> 项目：国家队ETF动向监控（etf-monitor）· v1.1.0（2026-10-04）
> 测试框架：Python 标准库 `unittest` + `unittest.mock`，**零新增依赖**，全部离线（不访问网络）。

---

## 1. 测试分层

| 层 | 覆盖内容 | 方式 |
|---|---|---|
| 单元测试 | storage upsert 语义、数据源字段解析、规则引擎真值表 | 固定报文 / 合成数据 |
| 集成测试 | update_once 两日管线（K线→快照→规则→图表） | mock 数据源函数 |
| 冒烟测试 | 全部 9 个 HTTP 端点、launchd 服务状态 | curl（对真实服务） |
| 人工验收 | 图表中文渲染/图例/单点可见性 | 读图检查 |

运行方法（项目根目录）：

```bash
.venv/bin/python -m unittest discover -s tests -v
```

测试对 `storage.DB_PATH`、图表目录打临时目录补丁，**不会碰真实数据**；
`mock.patch` 替换 `datasource.fetch_*`，**不会发起网络请求**。

## 3. 缺陷 → 回归用例映射（v1.1.0 审查修复项）

| 缺陷 | 等级 | 修复 | 回归用例 |
|---|---|---|---|
| F1 K线回填覆盖份额来源 → 规则永远热身 | 致命 | K线行 source=NULL + COALESCE 保留 | S2、P1 |
| F2 份额聚合缺"全覆盖"校验 → 缺一只制造假赎回 | 致命 | 覆盖不全的日期不参与环比 | R8、R9 |
| F3 drop5/ret20 为 None 时信号消息格式化崩溃 | 中 | 消息分段拼装 | R3、R1/R4 |
| F4 单只K线失败中止整轮更新 | 中 | 逐只 try/except，快照按 quote_date 独立入库 | P2 |
| F5 快照全失败仍标记"今天已更新" → 当天不再重试 | 中 | 失败连击计数，3 轮封顶 | P3 |
| F6 趋势图 days 参数被缓存图忽略 | 低 | 按天数缓存 `{code}_d{days}.png` | 冒烟（days=250） |
| F7 价格图例被信号图例覆盖 | 低 | 合并为一个图例 | 人工验收 |
| F8 看板/summary 份额日变动跨源比较 | 低 | 仅同源相邻两日才计算 | R9 间接覆盖 |

## 5. 已知限制与后续建议

- 节假日无真实交易日，无法端到端验证"收盘后自动触发"路径（调度逻辑有单元级保障；可观察到首个交易日 15:45 后 `last_full_update` 是否自动变为当天）；
- 数据源字段位依赖（尤其腾讯快照的 p[37]/p[45]）已被 D3 固化，但若上游改版需按此定位修码；
- 建议每季度运行一次全量 `update.py --force` 并抽查 `/api/details` 与腾讯 App 行情对照。
