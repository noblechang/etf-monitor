# 01 · 需求文档

> 项目：国家队ETF动向监控（etf-monitor）
> 版本：v1.1.0（2026-10-04）
> 状态：已交付上线（launchd 常驻运行）

---

## 1. 背景

"国家队"（中央汇金及其持牌机构、证金公司等）自 2023.10 起通过增持宽基 ETF 入市维稳，
2024–2025 年以单边增持托底为主；自 2026 年起转为**双向操作**：

- **跌时进场**：市场急跌日大额净申购宽基 ETF（如 2026-07 形态）；
- **高位撤退**：市场亢奋时大额净赎回（如 2026-01、2026-04/05 形态）。

国家队持仓规模约 4.4 万亿元，高度集中于沪深300/上证50 系宽基 ETF。
对个人投资者的意义不是抄它的持仓，而是把它当**市场情绪的锚**：

> 恐慌时它进场 → 底部区域参照；亢奋时它撤退 → 不追高警示。

ETF 场内份额的日度变动是这一行为**可公开观测的技术代理**。

## 2. 目标

| # | 目标 |
|---|---|
| G1 | 自动、每日、免维护地采集 8 只汇金系重点宽基 ETF 的行情与场内份额 |
| G2 | 把既定判断规则自动跑成信号，不依赖人工盯盘 |
| G3 | 支持客户/调用者随时查询：**每日明细、趋势图、两条规则的结果** |
| G4 | 数据口径可靠：不因数据源切换/缺数输出假信号 |

## 3. 非目标（范围外）

- 不区分申购/赎回方的身份（汇金/险资/其他大机构无法从公开数据区分），份额变动是**概率参照而非确证**；
- 不覆盖场外联接份额、券商自营盘；
- 不做自动交易、不推送实盘指令；本工具仅整理公开数据，**不构成投资建议**；
- 不做多机部署/鉴权（单机本机服务形态）。

## 4. 用户与场景

| 用户 | 场景 |
|---|---|
| 个人投资者 | 每天收盘后约 5 分钟：打开网页看板，看规则结果 + 持仓明细 + 趋势图 |
| 程序/脚本调用者 | 通过 HTTP API 拉取明细、趋势图、规则结果，做二次加工或告警 |
| 维护者 | 调整监控标的与阈值、排查数据问题 |

## 5. 功能需求

### FR-1 数据采集
- 覆盖 8 只 ETF（510300/510310/159919/510050 = 沪深300+50 系；510500/512100/159977/588000 = 宽基系），标的清单可配置；
- 历史K线一次回填 ≥ 500 个交易日（收盘价、成交量）；
- 每交易日收盘后采集当日场内份额（主源东财 f84，备用腾讯"总市值/现价"反推）；
- 单一数据源故障不中断采集（自动降级）。

### FR-2 数据存储
- 本地 SQLite 落盘，字段含：收盘、涨跌幅、成交量、成交额、份额、规模、来源；
- 重复更新幂等（同日重跑不产生脏数据、不覆盖有效字段）；
- 保留来源字段以支撑口径校验。

### FR-3 判断规则（自动执行）
- **规则一 `BOTTOM_BUY_REF` 底部买入参照**：基准ETF大跌（单日 ≤ -1.5% 或 5日 ≤ -4.0%）
  **且** 沪深300系份额日增 ≥ 0.8%（或 ≥ 0.3% 且成交量为 5 日均量 ≥ 2 倍）→ 信号；
- **规则二 `AVOID_CHASE` 高位不追/止盈警示**：20日涨幅 ≥ 8%（或价格处于近 120 日 90% 分位上方）
  **且** 份额连续 4 日下降、累计 ≤ -1.0% → 信号；
- 两规则均未触发时明确输出"无信号"状态；
- 信号带证据（触发当日的各指标值）与强度分级（strong/medium）；
- 阈值可配置。

### FR-4 份额数据热身期
- 部署后份额数据逐日积累，同源数据不足 5 个交易日时规则不生效，
  输出 `warming_up` 状态而非伪信号。

### FR-5 明细查询（客户）
- 按标的、日期区间、条数查询每日明细（收盘/涨跌幅/成交额/份额/规模）。

### FR-6 趋势图（客户）
- 单 ETF 三联图：价格+MA20 / 成交额 / 份额，信号日在图上以竖虚线标注（红=底部参照，橙=高位警示）；
- 组合汇总图：基准ETF价格 + 汇金系合计份额；
- 支持指定区间天数。

### FR-7 规则结果查询（客户）
- 查询当前规则状态（warming_up / 无信号 / 各信号）与历史信号列表；
- 查询规则定义与阈值。

### FR-8 网页看板与自动更新
- 一个网页汇总：规则结果、8 只 ETF 最新明细表、全部趋势图；
- 交易日收盘后（15:45）自动更新；机器当时关机，开机后自动补跑；
- 服务随系统自启、崩溃自动拉起（launchd）。

## 6. 非功能需求

| # | 需求 | 实现 |
|---|---|---|
| NFR-1 口径正确性 | 份额只做同源、同覆盖度的比较，杜绝跨源/缺数假信号 | 同源守卫 + 全覆盖聚合（见设计文档 D2/D3） |
| NFR-2 可靠性 | 网络抖动退避重试；单源故障降级；单标的失败不影响整轮 | 3 次退避重试、EM→腾讯降级、4 节点轮换 |
| NFR-3 请求克制 | 对数据源低频请求，避免触发限流 | 一天一轮全量 + 5 分钟级检查；逐只间隔 1s |
| NFR-4 隐私与安全 | 全部数据本地落盘；服务只监听 127.0.0.1 | SQLite 本地文件；bind 127.0.0.1 |
| NFR-5 低维护成本 | 无需人工干预的日常运行 | launchd 常驻 + 内置调度 + 补跑 |
| NFR-6 可测试 | 核心逻辑可离线回归 | 31 个单元/集成用例，纯标准库 |

## 7. 验收标准（交付时已全部通过）

1. `update.py --force` 一次完成 8 只 ETF × 550 日K线回填 + 当日份额快照 + 规则评估 + 9 张图表生成；
2. `/api/details`、`/api/etf/{code}/trend.png`、`/api/signals` 三个客户接口按上文 FR-5/6/7 工作正常；
3. 次日再跑更新后，前一日份额与其来源**不被覆盖**（回归用例 test_two_day_run_preserves_share_source）；
4. 组内某只当日缺数时，该日份额环比不参与计算，不输出信号（回归用例 test_partial_coverage_day_excluded_from_inflow）；
5. 服务经 launchd 常驻，重启后自启并自动补跑；
6. 全部图表中文渲染正常、单点份额数据可见。

## 8. 约束与假设

- 运行环境：macOS（Python ≥3.9 系统解释器即可，无需新依赖之外的运行时）；
- 假设东财/腾讯公开行情接口结构在其文档化字段位上保持稳定（已用固定报文测试固定）；
- 节假日无新数据，服务照常运行，下一交易日 15:45 后自动恢复更新。
