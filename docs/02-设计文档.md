# 02 · 设计文档

> 项目：国家队ETF动向监控（etf-monitor）· v1.1.0（2026-10-04）

---

## 1. 总体架构

```
                 ┌────────────────────────── launchd 常驻进程 ──────────────────────────┐
                 │                                                                      │
  数据源          │  etf_monitor/ 包                                                     │  消费者
┌──────────┐     │  ┌────────────┐   ┌──────────┐   ┌─────────┐   ┌──────────┐          │  ┌───────────┐
│ 腾讯K线   │◄────┼──┤ datasource ├──►│ storage  │◄──┤  rules  │   │  charts  │          │◄─│ 网页看板 / │
│ 东财快照  │     │  │ (抓取+降级) │   │ (SQLite) │   │(规则引擎)│   │(matplotlib)│         │  │ HTTP API  │
│ 腾讯快照  │◄────┼──┤            │   └────┬─────┘   └────┬────┘   └────┬─────┘          │  └───────────┤
└──────────┘     │  └────────────┘        ▲              │             │                │       ▲      │
                 │                   ┌────┴──────────────┴─────────────┴─────┐          │       │      │
                 │                   │             updater（编排）            │          │  server.py   │
                 │                   │  幂等更新 / 调度线程 / 失败重试上限    │◄─────────┼──────────────┤
                 │                   └──────────────────┬────────────────────┘  触发更新 │  FastAPI     │
                 │                                      ▼                               │  + 调度启动   │
                 │                          data/etf.db · output/charts/*.png           │              │
                 └──────────────────────────────────────────────────────────────────────┘
```

- **datasource**：只管抓取与解析，带退避重试与降级；无业务判断。
- **storage**：SQLite（WAL），线程安全（写锁 + 每操作独立连接）；upsert 全字段 `COALESCE`。
- **rules**：纯读库评估，写 `signals` 表与 `last_rule_status` 元信息。
- **charts**：matplotlib Agg 后端，静态 PNG 落盘。
- **updater**：编排上述四者；幂等（一天最多一轮，可 force）。
- **server**：FastAPI，提供 API 与看板；启动即补跑当日漏掉的更新。

目录结构：

```
etf-monitor/                 （真实位置 ~/Library/Application Support/etf-monitor，
                               ~/Documents/projects/etf-monitor 为软链接）
├── config.json              监控标的 + 规则阈值 + 服务参数

├── tests/                   单元 + 集成测试（纯标准库）
├── data/etf.db              SQLite（WAL）
├── output/charts/*.png      每日重绘的 9 张图
├── logs/server.log(.err)    launchd 标准输出/错误
└── docs/                    本文档体系
```

## 2. 数据模型

### 2.1 `daily`（每日行情+份额，主键 code+date）

| 字段 | 说明 | 写入方 |
|---|---|---|
| close | 收盘价（K线为前复权口径） | K线；当日由快照现价覆盖 |
| pct_chg | 涨跌幅 % | K线逐日补算；当日由快照覆盖 |
| volume | 成交量（份，手×100） | K线 |
| amount | 成交额（元，真实值） | 仅腾讯快照日有 |
| amount_est | 成交额估算 = 量×收盘价 | K线日 |
| shares | 场内份额（份） | 快照 |
| scale | 基金规模（元） | 快照 |
| source | 该行份额/快照的来源：`eastmoney` / `tencent`；纯K线行为 NULL（历史遗留 `tencent_kline` 等价于 NULL） | 快照 |

**upsert 语义（口径基石）**：所有字段 `COALESCE(excluded.X, daily.X)`——后写入方只填自己的字段，
传 `NULL` 不覆盖已有值。K线回填固定传 `shares/scale/source = NULL`，保证次日回填不会抹掉快照写入的份额与来源。

### 2.2 `signals`（主键 date+rule）

`date, rule(BOTTOM_BUY_REF|AVOID_CHASE), level(strong|medium), message, evidence(JSON), created_at`

### 2.3 `meta`（键值）

| 键 | 含义 |
|---|---|
| last_full_update | 最近一次完整更新日期（幂等控制；快照全失败时当天最多重试 3 轮才标记） |
| last_data_date | 数据的最新交易日 |
| last_rule_status | 最近一次规则评估的完整结果 JSON |
| snapshot_fail_streak | 快照连续全失败轮数（当天重试上限控制） |

## 3. 更新管线（update_once）

```
1) K线回填   每只ETF：腾讯 ifzq 拉 550 日 → 逐日补算 pct_chg → upsert（source=NULL）
             单只失败 → 记入摘要，不中止整轮
2) 份额快照  每只ETF：东财 push2（4 边缘节点轮换）→ 失败降级腾讯 qt → 逐只间隔 1s
             quote_date 不在K线日期内 → 退回K线最新交易日，且不覆盖该日价格
             全部失败 → 不标记完成，调度器 5 分钟后重试；连续 3 轮全失败放弃当天
3) 规则评估  rules.evaluate() → 写 signals + last_rule_status（失败不阻塞更新）
4) 图表重绘  8 张单ETF图 + 1 张组合图（失败不阻塞更新）
5) 收尾      last_full_update / last_data_date / updated_at
```

自动触发：服务内置调度线程每 300 秒检查一次 `should_update_now()`（周一~周五、时刻 ≥ 15:45、今天未标记完成）；
服务启动时若当天未更新则后台补跑；launchd 保证进程开机自启与崩溃拉起。

## 4. 关键设计决策

### D1 份额只信"同源 + 全覆盖"的日环比
东财 f84（场内份额权威口径）与腾讯"总市值/现价"反推的份额存在 0.2%~3% 固定口径差；
组内缺任何一只（如缺 588000，占比可达 40%+）都会把合计拉出巨额假变动。因此：

1. 以**最新有份额那天的来源**为基准（`t_src`），逐日只聚合来源相同的行；
2. 该日组内**全部 ETF** 都有同源份额才收录，覆盖不全的日期不参与环比；
3. 来源切换日（如东财全天限流降级腾讯）热身天数重新计数——宁可延迟生效，不输出伪信号。

### D2 热身期（WARM_DAYS=5）
同源份额不足 5 个交易日时，规则输出 `warming_up`（含进度 n/5 与来源），`signals` 恒为空。

### D3 K线回填不携带来源（v1.1.0 修复）
v1.0 的 K线 upsert 带 `source="tencent_kline"`，次日回填会覆盖快照写入的 `eastmoney`，
导致同源聚合只剩最新一天、规则**永远热身**。修复后 K线行 `source=NULL`（见 2.1）。

### D4 成交额口径
腾讯日线无成交额，K线日存 `amount_est = 量×收盘价`；仅用于**同口径比值**（放量倍数），
快照日存真实 `amount`。规则中比较的是"当日 / 前5日均值"，两侧口径一致即可用；
展示层标注"亿,估"。

### D5 网络与限流
- 共享 `requests.Session` 且 `trust_env=False`：绕过 macOS 系统代理（Clash 等境外出口会被东财拒绝）；
- 所有请求 3 次退避重试（2s/4s/6s）；东财快照在 4 个边缘节点间轮换；
- 请求节奏：一天一轮（每只 1 次 K线 + 1~2 次快照），逐只间隔 1s。

### D6 降级矩阵

| 故障 | 行为 |
|---|---|
| 东财快照失败（单只） | 降级腾讯快照（份额=总市值/现价，source=tencent） |
| 东财+腾讯都失败（单只） | 该只当日无份额行，规则侧该日不参与聚合 |
| 腾讯K线失败（单只） | 该只跳过K线；快照仍按 quote_date 入库；整轮不中止 |
| 快照全部失败（整轮） | 不标记完成 → 调度器自动重试；连续 3 轮全失败放弃当天 |
| 规则/图表异常 | 记入摘要，不影响数据入库 |

### D7 规则引擎计算细节
- 价格基准：按 `510300 → 510310 → 159919 → 510050` 优先级取有数据的第一只；
- 份额基准：沪深300系 4 只合计（`agg_hs`）；全组合 8 只合计仅作 evidence 参考值；
- `day_inflow(d)` = 当日合计 / 前一交易日合计 − 1（任一日缺失/覆盖不全 → None）；
- 90 分位：近 `high_pctile_days`(120) 个交易日收盘价的排序分位，样本 < 60 日不计算；
- 规则一强度：`drop1 ≤ -1.5% 且 inflow ≥ 0.8%` → strong，否则 medium；
- 规则二强度：累计赎回 ≤ -2.0%（阈值的 2 倍）→ strong，否则 medium；
- "连续4日下降"实现为：今日 inflow<0 且此前 3 日 inflow 均存在且 <0，4 日合计 ≤ -1.0%
  （中间任何一日缺数即视为连续性破坏，不触发）。

### D8 图表
- 单ETF三联图（价格+MA20 / 成交额柱 / 份额），组合图（基准价 + 两组合计份额）；
- 信号日竖虚线：红=BOTTOM_BUY_REF，橙=AVOID_CHASE；
- 份额点 < 3 个时用圆点标记保证单点可见，并注明数据起始日；
- 120 天版由每日更新预生成；其他天数按 `f"{code}_d{days}.png"` 按需渲染并缓存；
- 合计份额曲线同样执行"全覆盖才计入"（D1），缺失日断线而非画出假跳变。

## 5. 配置（config.json）

| 键 | 默认 | 说明 |
|---|---|---|
| listen_host / listen_port | 127.0.0.1 / 8686 | 服务绑定地址（无鉴权，勿改为 0.0.0.0） |

| etfs[] | 8 只 | code/symbol(腾讯)/secid(东财)/name/group(hs300\|broad) |
| rules.bottom_buy | drop_1d_pct -1.5 / drop_5d_pct -4.0 / inflow_1d_pct 0.8 / inflow_1d_pct_vol 0.3 / vol_multiple 2.0 | 规则一阈值 |
| rules.avoid_chase | high_20d_pct 8.0 / high_pctile 90 / high_pctile_days 120 / redeem_days 3 / redeem_total_pct -1.0 | 规则二阈值 |
