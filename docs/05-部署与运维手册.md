# 05 · 部署与运维手册

> 项目：国家队ETF动向监控（etf-monitor）· v1.1.0

---

## 1. 安装位置（重要）

| 路径 | 角色 |
|---|---|
| `~/Library/Application Support/etf-monitor/` | **真实安装目录**（launchd 服务从这里运行） |
| `~/Documents/projects/etf-monitor` | 指向上面的**软链接**，日常从这里进即可 |

不装在原计划的 `state-backed funds$state` 目录的两个原因：
1. 目录名含 `$`，pip/venv 会把它当环境变量解析直接报错（`ValueError: invalid variable '$state'`）；
2. macOS 隐私保护（TCC）**禁止 launchd 进程读取 ~/Documents**，服务会启动失败（exit 78）。

## 2. 全新部署

```bash
cd ~/Documents/projects/etf-monitor
bash setup.sh                        # venv + 依赖（自动区分 Python 3.9/3.10+ 的 get-pip）
.venv/bin/python update.py --force   # 回填 550 日K线 + 当日份额快照 + 规则 + 图表
bash install_launchd.sh              # 注册 launchd：开机自启、崩溃拉起、交易日 15:45 后自动更新
```

## 3. 升级 / 重启 / 卸载

```bash
# 重启服务（加载新代码）
bash install_launchd.sh
# 等价于：launchctl unload ~/Library/LaunchAgents/com.statefunds.etfmonitor.plist && launchctl load ...

# 查看状态（第一列 PID，第二列上次退出码）
launchctl list | grep etfmonitor

# 卸载
launchctl unload ~/Library/LaunchAgents/com.statefunds.etfmonitor.plist
rm ~/Library/LaunchAgents/com.statefunds.etfmonitor.plist
```

## 4. 配置项（config.json）

| 键 | 默认 | 说明 |
|---|---|---|
| listen_host / listen_port | 127.0.0.1 / 8686 | **无鉴权服务，勿改为对外地址** |
| update_time | "15:45" | 交易日自动更新时刻（A股收盘后） |
| history_days | 550 | K线回填天数（也是 trend.png days 上限） |
| etfs[] | 8 只 | code/symbol（腾讯 sh|sz 前缀）/secid（东财 1.|0. 前缀）/name/group |
| rules.* | 见设计文档 §5 | 两条规则阈值，改后 `update.py --force` 生效 |

增删标的：在 `etfs` 数组加一行（三套代码前缀必须配套），重启服务即可；`group` 决定它进哪个份额合计。

## 5. 数据与备份

| 路径 | 内容 | 建议 |
|---|---|---|
| `data/etf.db` | 全部行情/份额/信号（SQLite，WAL 模式） | 定期整文件拷贝即完整备份（建议连 `-wal`/`-shm` 一起，或先停服务） |
| `output/charts/` | 9 张 PNG，每日重绘 | 可随时删除，下次更新自动重建 |
| `logs/server.log` `.err.log` | launchd 标准输出/错误 | 异常排查第一入口 |

磁盘占用：当前 DB ≈ 0.5MB、图表 ≈ 1.2MB；按 550 日滚动不增长（K线窗口固定）。

## 6. 日常运维

- **看状态**：`curl http://127.0.0.1:8686/api/summary` → `updated_at` 是否为今天；
- **手动更新**：`.venv/bin/python update.py --force`（输出完整摘要 JSON）或 `POST /api/update`；
- **看日志**：`tail -50 logs/server.log logs/server.err.log`（调度器触发/失败均有打印）；
- **节假日**：无数据更新属正常，服务照常运行；下一交易日 15:45 后自动恢复。

## 7. 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 东财快照失败 / 规则显示来源 tencent | 东财限流或系统代理干扰 | 已自动降级腾讯口径，无需处理；次日东财恢复自动切回 |
| Python 报 ProxyError 而 curl 正常 | macOS 系统代理（Clash 等）注入 | 代码已用 `trust_env=False` 规避；勿删除该行 |
| launchd 启动失败 exit 78、日志无输出 | TCC 禁止读 ~/Documents | 确认服务仍从 `~/Library/Application Support` 运行，勿把真实目录搬回 Documents |
| pip/venv 报 `invalid variable` | 目录名含 `$` | 同上，保持在当前安装位置 |
| `/api/signals` 一直 warming_up | ①部署不足 5 个同源交易日（正常）②长期无东财/腾讯同源连续数据 | 看 message 中的 n/5 与来源；连续多日不变再查日志 |
| 规则从不触发 | 属正常状态（两条规则是"形态警报"不是日常状态） | 无信号=按自己计划执行 |
| 份额日变动显示 "-" | 前后两日来源不同，已按口径守卫禁止跨源计算 | 正常行为，次日同源后恢复 |
| 端口被占 | 其他进程占用 8686 | 改 config.json 的 listen_port 并重启 |

## 8. 安全说明

- 服务只绑定 `127.0.0.1`，无鉴权；不要把 `listen_host` 改为 `0.0.0.0`；
- 所有数据来自公开行情接口，本地落盘，不外发任何信息；
- `POST /api/update` 触发的是幂等更新，无破坏性。
